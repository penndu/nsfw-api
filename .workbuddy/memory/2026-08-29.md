## nsfw-api 代码分析（杜老师让"分析代码"）

**项目**：nsfwjs-api，4 个 TS 文件的 NSFW 图像识别 API 包装器，基于 Express + @tensorflow/tfjs-node + nsfwjs + simple-ts-express-decorators + multer。

**结构**：
- `src/index.ts` 入口（21 行）
- `src/NsfwImageClassifier.ts` 核心（单例懒加载模型、`Promise.all` 并发 decode+load、`image.dispose()` 释放张量）
- `src/config/model.ts` MODEL_SIZE 环境变量覆盖，默认 299
- `src/controllers/NsfwController.ts` 两个路由：/classify（单图）、/classify-many（最多 10 张）
- `models/default/`（22 分片 ~84MB，299×299 完整版）和 `models/min/`（6 分片 ~21MB 量化版）

**提的改进点**（按优先级）：
1. 🟡 `classifyMany` 无并发限制 → 建议加 p-limit（建议并发 2~3）防 TFJS OOM
2. 🟡 缺图返 410 Gone 不合语义 → 改 400 Bad Request
3. 🟡 端口硬编码 3000、无 SIGTERM → 加 process.env.PORT + server.close()
4. 🟢 无 body 大小限制 → 加 express.json({limit}) 防 DoS
5. 🟢 Dockerfile 用 `ARG modelType` 构建时切换 default/min ✅

**Dockerfile 注意**：用 `node:lts-slim` + 装 python3/build-essential 让 tfjs-node 走本地编译，`COPY ./models/$modelType ./model` 直接嵌模型进镜像（无版本管理）。

**杜老师后续可能的方向**（待他确认）：限流版改造 / OpenAPI 文档 / Dockerfile 多阶段构建缩体积。

## Node 24 兼容：polyfill util.isNullOrUndefined / util.isArray（杜老师报 tfjs 崩）

**问题**：在 Node 24 (`v24.20.0`) 上 `yarn start` 立即崩：
```
TypeError: (0 , util_1.isNullOrUndefined) is not a function
    at createTensorsTypeOpAttr (nodejs_kernel_backend.js:675:38)
```

**根因**：tfjs-node 4.22.0 内部用 `util.isNullOrUndefined` / `util.isArray`，Node 22 上还能跑（已 deprecated 但还可用），Node 24 直接移除。修复在 tfjs#8425 已合并，但**没发布新版本**（tfjs#8609，4.23.0-rc.0 仍卡在 RC，maintainer mattsoulanille 没出 stable）。

**方案**：拆文件 polyfill（不能用单文件内 polyfill，因为 `import * as tf from '@tensorflow/tfjs-node'` 会被 TS hoist 到顶，polyfill 赋值赶不上 tfjs 模块初始化）。
- `src/util-polyfill.ts`：检测 `typeof !== 'function'` 时用 polyfill 补回
- `src/index.ts`：把它放在 `import 'reflect-metadata'` 之后、`import express` 之前，保证 tfjs-node 被 require 之前 polyfill 已生效

**模拟验证**（Node 22 上 delete util API 模拟 Node 24）：
- 写 `smoke-node24.js`：`delete util.isNullOrUndefined; delete util.isArray;` 后 `require('./index.js')`
- /classify → 200 OK
- /classify-many → 200 OK
- SIGTERM 优雅退出
- **没有 DEP 警告**（之前因为 util.isNullOrUndefined 还在所以刷警告）

**待清理**：tfjs-node 一旦发布 4.23.0+ stable 就可以删 polyfill + 删除 `app/util-polyfill` import。注释里写明引用了 tfjs#8425 / #8609 方便未来追溯。
